# 萌兽卡丁 · Moe Kart

网页版 Q 版卡通竞速游戏，参考跑跑卡丁车的道具竞速玩法，美术与代码全部原创。
纯前端实现——**HTML + CSS + 原生 ES Module + Three.js**，无框架、无构建步骤，克隆下来打开就能玩。

> 项目文件夹名沿用开发期的 `the king of driver`，游戏正式标题是「萌兽卡丁 · Moe Kart」。

## 在线游玩

- 单机版（GitHub Pages）：https://lzfxisxji.github.io/the-king-of-driver/
- **联机对战**：GitHub Pages 只托管静态站点、不会运行 WebSocket 服务器，公网联机需要另行部署 `server/server.js`（或用支持 WebSocket 的 PaaS / 反代），再把地址通过 `?ws=wss://你的服务器:端口` 传给页面。本地联机可直接用下面「本地运行」里的服务器，无需任何外网配置。

## 玩法

5 人（1 名玩家 + 4 名电脑）同场竞速，5 圈定胜负。赛道是圆角矩形闭环，共 5 条车道，全程第三人称跟车视角。

主菜单点「练习模式」即可与 4 名电脑玩家同场竞速；点「联机对战」则能与好友联机（详见下节）。

| 操作 | 按键 |
|---|---|
| 加速 | `W` / `↑` |
| 刹车 / 倒车 | `S` / `↓` |
| 左右变道 | `A` `D` / `←` `→` |
| 氮气加速 | `Space`（消耗体力） |
| 使用道具 | `E` |
| 暂停 / 退出确认 | `Esc`（练习模式会冻结比赛） |
| 静音开关 | `M`（或点右上角 🔊 按钮） |

- **体力条**：氮气消耗、松开后自动回复；体力耗尽无法加速。
- **道具**（撞到赛道上的道具箱随机获得，名次越靠后越容易拿到攻击性道具）：
  - 🍌 **香蕉皮** —— 选好车道后向后投放，后面踩到的车会打滑
  - 🖤 **墨水** —— 遮挡前方对手的视野
  - 💚 **药水** —— 立即回复大量体力
  - ⚡ **闪电** —— 让其余所有对手短暂减速
  - 🚀 **导弹** —— 锁定前方最近的对手发射，命中即打滑（名次越靠后越容易拿到）
  - 🛡 **护盾** —— 6 秒内免疫香蕉 / 导弹 / 墨水 / 闪电（名次越靠前越容易拿到）
- **弯道抓地**：过弯速度过高会向外侧滑，需要适当松油门。
- **音效**：全部由 WebAudio 实时合成（无音频素材文件），含引擎声、道具音效与轻量背景音乐；按 `M` 可一键静音。

## 联机对战

点主菜单「联机对战」即可与好友同场竞速——**输入 4 位房间号**或**直接从房间列表里挑一间进**，每间最多 6 人，服务器同时最多开 10 间房。

**玩法**

1. 主菜单点「联机对战」，确认当前角色 / 车辆（可返回上一步更换）。
2. 页面上会显示连接状态与**房间列表**（房号 / 房主 / 人数 / 是否已开赛，最多 10 间，每 2 秒自动刷新，房间有增减时服务器会主动推送）；点任意一间「进入」即可入房，也可以手动输入房间号加入。
3. 「创建房间」会生成 4 位房间号（已剔除易混字符 I/O/0/1），把房间号发给好友。
4. 房主在房间大厅点「开始游戏」即发车；其余玩家点开始后自动进入。

> 没连上服务器时，「创建房间 / 加入房间」按钮会置灰，顶部会给出明确提示——不会再出现"点了没反应"。

**架构（房主权威中继）**

- 一个轻量 Node 服务器（`server/server.js`，基于 `ws`）**只做消息中继与房间管理，不跑任何游戏逻辑**。
- **房主本地运行完整比赛模拟**，每 50ms 把赛道快照广播给其他人；其他玩家只把按键输入发给房主，并按快照插值渲染。
- 这样单机 `Race` 逻辑被完全复用，服务器极轻、无状态，延迟主要在房主与客人之间的快照 / 输入往返。

**本地联机（两台设备在同一网络，或直接本机开两个标签页测试）**

先起 WebSocket 中继服务器，再起静态站点：

```bash
npm install          # 安装 ws 依赖（首次）
npm start            # 启动中继服务器，默认 ws://0.0.0.0:8080（可用 PORT 环境变量改端口）
python serve.py      # 静态站点 http://127.0.0.1:8231
```

浏览器开 `http://127.0.0.1:8231`，点「联机对战」即可。同一台机器想开两个客户端联机自测时，开两个浏览器标签页、一个创建房间、另一个加入即可（注意两个标签页会各自占用一套键盘输入，建议用两台设备体验最直观）。

**公网联机部署提示**

- GitHub Pages、普通静态托管都**不会**运行 `server/server.js`，所以页面上的「联机对战」在纯静态托管下连不上服务器（顶部会明确提示「连不上联机服务器」）。
- `server/server.js` 是**单端口**应用：默认同端口托管整个静态站点（`SERVE_STATIC=0` 可关掉）。所以把它部署到任意支持 WebSocket 的 Node 环境（Railway、Render、Fly.io、自有服务器 / 反代），**直接用部署出来的那个地址打开页面就能联机**，不需要再单独配静态托管、也不用加 `?ws=`。
- 静态托管带安全屏蔽：只发仓库内的普通文件，`.git` / `.workbuddy` 等点目录与 `node_modules` 一律 403，并带 `Cache-Control: no-store`。
- 服务器默认端口 8080，可用 `PORT` / `HOST` 环境变量覆盖；`MAX_PLAYERS`（每间房人数，默认 6）与 `MAX_ROOMS`（同时存在的房间数，默认 10）在 `server/server.js` 内常量调整。
- 改了 `server/server.js` 后需要**重启** `npm start` 才会生效。

## 角色与车辆

6 名角色 × 9 辆车，全部同性能，纯外观差异。

| 角色 | 称号 | 类型 |
|---|---|---|
| 噜噜 | 胡萝卜小胖 | 均衡型 |
| 肥嘟袋鼠 | 拳击袋鼠 | 力量型 |
| 奶龙 | 呆萌奶龙 | 可爱型 |
| 牛来 | 壮实小牛 | 稳重派 |
| 豆包 | 黑风少女 | 灵巧型 |
| 老司机 | 方向盘执念 | 隐藏角 |

车辆为 5 辆跑车 + 4 辆轿车，**全部是敞篷 / 开放驾驶舱造型**，角色真正坐在驾驶位里（不是「人物图 + 汽车图」两张立绘叠加）。

## 本地运行

游戏用 ES Module 加载代码，**必须通过 HTTP 访问**，直接双击 `index.html` 会被浏览器的同源策略拦下。

**方式一（推荐）**：双击 `启动游戏.bat`，脚本会自动挑一个能用的 Python、起本地服务并打开浏览器。

**方式二**：自己起一个静态服务，例如

```bash
python serve.py          # 默认 http://127.0.0.1:8231
```

`serve.py` 带 no-cache 头，改完代码刷新即生效，不会吃到浏览器缓存。

**方式三（想联机就用这个）**：中继服务器本身也能同端口托管整个站点，一条命令同时提供页面与联机：

```bash
npm install              # 首次安装 ws
npm start                # 打开 http://127.0.0.1:8080 即可游戏，联机也已就绪
```

页面对 ws 地址是自动判断的：跑在 8231 时连本机 `:8080`，其余情况一律用「同源」，
所以无论用哪种方式起服务，都不用额外配 `?ws=`。如果页面与中继不同源，再手动加
`?ws=wss://你的服务器:端口` 覆盖即可。

## 技术要点

- **解析式赛道**：赛道用 `(s, lat)` 参数化描述，配 SDF 判定内外，所以 AI 寻路和出界检测都是纯数学，不依赖物理引擎。
- **立绘合成驾驶位**：所有角色统一到一张 240×320 画布，方向盘 / 座位锚点写死为画布比例。换车换人只换图片，位置与尺寸由 `config.js` 的 `carSize()` / `driverMetrics()` 推导，比赛画面和选人预览共用同一套度量，因此预览里看到什么比例，实机就是什么比例。
- **遮挡靠 renderOrder**：角色和车都是平面立绘（`MeshBasicMaterial({transparent, depthWrite:false})`），靠 `renderOrder` 让车盖住角色下半身。这里踩过坑——顺序反了角色平面会把整辆车糊掉。
- **两套驾驶位贴图**：背面（比赛第三人称）和正面（选人页正对玩家），骨架完全一致所以切换无跳变。
- **电脑玩家与玩家同一套速度基准**：极速 / 氮气极速 / 加减速曲线完全共用 `PHYS.maxSpeed` / `PHYS.boostSpeed`，AI 只在 `config.js` 的 `AI` 块里做两点微调——`skillMin ~ skillMax`（默认 0.975~1.0，即最多慢 2.5%，用来让电脑玩家之间略有强弱）与「弯道速度剖面 + 氮气节奏」。
- **AI 的速度决策按赛道速度剖面算**：抓地极限是 `v²·κ ≤ gripLimit`，所以每段路的安全速度 `vSafe = √(gripLimit/κ)`；再按制动能力反推「离这段路还有 d 时最多能开多快」`vAllow = √(vSafe² + 2·a·d)`，取整条视距内的最小值。这样该刹的地方刹、该全油门的地方全油门，而不是一看到前方有弯就提前几十米收油。
- **极速是硬夹紧的**：超速后按固定速率回落，并额外夹一个「极速 + 小余量」的硬上限。只写 `max(v, v - Δ)` 的话，加速比回落快时速度会一路往上漂（曾经把 38.5 的氮气极速漂到 47）。

## 已知限制

- 老司机角色只有一张正面素材，比赛中仍面朝镜头，与其他角色的背影视角不一致。
- 移动端未做触屏操作适配，目前建议用键盘。
